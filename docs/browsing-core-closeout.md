## 2026-10-09：0.6.0大PNG缩放反馈修复

以下为0.6.0候选源码的新预算与验证，后文0.5原验收数据保持历史值；已有公开Pre-release资产不自动更新。

- 用户反馈的PNG为4944×6456、16位RGB、非交错；显示BGRA需127,673,856字节（121.8MiB），超过原完整细节92MiB。原路径只保留中心区域，新的缩放矩形即使被原区域覆盖也会重开文件；WIC/native可能读取区域之外，输出16MiB不能代表解码成本。
- 主图输出政策调整为192MiB，仍预留两份32MiB预览及4MiB邻图，完整细节最多124MiB。首次按需完整读取后保留到切图、F5、清图或关闭；普通图按真实尺寸分配，不预分配192MiB。动画源画布准入独立保持92MiB/单输出8MiB/交接32MiB。
- 已保留区域覆盖新请求时直接复用；在途区域覆盖新请求时保持原解码。请求超出区域仍会重新读取，继续只有一块2048×2048/16MiB区域，未实现完整分块或全图无界缓存。
- 本地Release构建0警告0错误；核心190+UI/codec414=604通过，1真实RAW样本跳过。新增3项有意义回归：约32MP完整细节只读一次并关闭释放、在途/保留子区域去重、真实WPF缩放区域请求次数；原四档DPI的自动细化测试增加20轮缩放/Fit/Actual后不重复解码断言，既有过期/取消/缓存/动画/多页回归保持通过。
- 显式开发probe命令：`dotnet run --project benchmarks/ModernImageViewer.CodecProbe -c Release -- browse-detail <受控静态样本>`。报告不含路径，不启动应用、不碰用户现有窗口或关联、不强制GC。只读真实反馈PNG：预览1次、完整1次、区域0次，后续20次细节请求使用同一份像素；保留127,673,856字节，清图后受控像素0字节/0项，原文件SHA-256前后一致。
- 单次framework-dependent观察预览1554.08ms、完整1751.24ms，工作集约166.77MiB/private143.21MiB。与本轮测试及格式检查并发，不作为前后性能对比、CPU降低百分比或P95；没有真实桌面鼠标验收、GPU/surface或整进程泄漏证明。原始报告在`artifacts/large-image-refinement/sample-detail.json`。Windows CI与最终本地打包结果随后按实际补录。

## 0.5历史验收

基线 master `25b9424`，开发版本仍0.5.0，公开下载仍v0.4.0。本轮不扩展编辑、标注、滤镜、批处理、完整RAW或其他大型功能，不触发Release。下面的能力属于开发代码，正式验证按末节记录。

## 发现与改动

- 固定2560×1600在普通窗口多解像素，大窗口/DPI不足。首屏改为可见画布DIP乘各轴DPI；目标4096单边/32MiB BGRA，源小于目标不放大。未布局回退旧目标。窗口350ms去抖，15%升级阈值避免抖动，不解更小替换；邻图首次显示不使用该阈值掩盖低分辨率。替换完成前保留旧画面。
- 信号量只有限并发，没有优先级。现在open/preview优先于full/region，内存图片读取也共用主槽；缩略图最多两槽，前台/细化等待或运行时不启动新缩略图，预取只用空闲主图槽。RAW/HEIF内部native单槽也使用相同优先顺序。已经运行的native不保证立即中断，取消后实际退出、释放晚结果才归还槽。
- 导航执行锁会丢弃连续同方向输入。现在累计待打开位置，允许导航命令接受新请求，只有最新代次可提交，反向也从待打开位置计算。
- F5原先到枚举结束才失效主图。现在刷新开始即取消open/detail/region/adaptive并清缓存；保存刷新目标和输入代次，后续切图不会被旧刷新抢回。切换会话取消旧预取、失效缩略图缓存。
- 主图、预览、区域解码前后复核长度和修改时间；细化提交与初始文件戳比较。变化或文件消失保留已显示图像，不混入新文件细节。文件戳不是内容哈希，同长度/时间变化仍需F5；无持续文件监听。
- 文件和内存来源统一使用identity决定视口保留。同来源预览升级保留缩放、平移、方向；同尺寸不同来源重置。DIP用于布局/平移/锚点，源像素用于坐标，物理像素仅在DPI/解码/绘制边界处理。浏览Fit不自动读取整图，排队的自动细化执行前复核当前需求；取消区域后预算拒绝不恢复加载状态。
- 卸载、重载与Dispose停止计时器、释放Skia/region/checker和像素pin；Dispose清绑定引用。细化不重复读取同源文件属性或重建未改变的缩略图带。原文件始终只读。

## 输出与缓存边界

| 资源 | 明确上限/规则 |
|---|---|
| 自适应主图预览 | 单边4096、BGRA32MiB；不超过源尺寸 |
| 主图输出预算 | 160MiB，完整细节最多92MiB，为两份32MiB预览和4MiB预取保守预留 |
| WIC区域 | 一份保留区域，最多2048×2048/16MiB，160ms去抖；方向临时像素仍按既有界限 |
| 邻图 | 一项、1280×800/4MiB；250ms延迟，忙时跳过，消费转移所有权 |
| 缩略图 | 224×140；最多两项在途，24项/2MiB LRU，不含可见项 |
| 阶段样本 | 仅显式开启，1024次请求/有界事件；不保留像素数组 |

主图预算从128MiB调整为160MiB，目的是覆盖4K而保留此前约92MiB完整细节能力。普通窗口按实际目标分配，不能由上限推断进程常驻内存增加或减少。以上不是native、surface、托管堆或整进程峰值硬上限，不将尚未实现的全管线预算写成已完成。

## 阶段观察

`scripts/measure-startup.ps1`保留。`scripts/measure-browsing.ps1`通过显式环境参数启用一次开发观察，调用正常导航/open/F5/实际像素API，不注入全局键鼠，不强制GC。未启用时不创建观察器或驱动、不采样、不写日志。报告不含图片路径、名称、EXIF或异常消息。

| 阶段 | 定义 |
|---|---|
| WindowVisible | WPF ContentRendered，观察器起点；进程创建耗时由startup脚本记录 |
| OpenRequested | VM打开入口收到请求并关联到coordinator代次；picker/direct coordinator回退Loading起点，不是OS激活收到时间 |
| FirstRecognizablePainted | 当前来源/请求/像素实际完成Skia绘制回调；不是人类辨认或GPU scanout证明 |
| NavigationAvailable | 当前目录索引/排序完成，含真实单文件目录；临时单项不计 |
| RequiredDetailPainted | 当前需求所需预览、完整像素或中心区域已绘制；整图不足预算单列DetailBudgetLimited |
| NeighborSwitchCompleted | 新请求首图绘制完成；细节阶段独立，不因取消晚结果误记完成 |

脚本记录环境、包类型、DPI、输出目标、阶段事件、WS/private/handle曲线、缓存/像素/pin快照和空闲趋势。生成样本交替64×64与2048×2048 PNG，文件互相独立，但色值每256项重复；不称为摄影语料。也可传入受控目录。固定Windows环境和相同样本/包参数可比，单次CI或压力运行不称P95、不承诺百分比提升。
