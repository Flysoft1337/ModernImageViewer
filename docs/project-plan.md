## 1. 项目定义

Modern Image Viewer 是一款面向 Windows 10/11 的本地图片查看器，重点解决三件事：

1. 快速打开并连续浏览本地图片；
2. 对截图、照片和素材完成常用调整与标注；
3. 不进入专业修图软件，也能可靠地另存或导出。

**产品主张：** 打开快、浏览稳、操作少、原图安全。

### 1.1 目标用户

- 需要替代 Windows 照片应用的普通用户；
- 经常查看、裁剪、缩放和分享截图的用户；
- 需要快速预览 RAW、设计素材或开发资源的摄影爱好者、内容创作者和开发者。

### 1.2 不以其为目标

本项目不替代 Photoshop、Lightroom、Affinity Photo 或 Paint.NET，不提供图层、复杂选区、通道、曲线、专业 RAW 调色和图像合成。

---

## 2. 产品原则

1. **浏览优先。** 新功能不得明显损害启动、切图、缩放和内存表现。
2. **原图安全。** 编辑默认存在于当前会话中；“保存”必须明确提示覆盖风险，默认推荐“另存为”。
3. **渐进解码。** 先显示有界降采样或内嵌预览，用户查看细节时按需细化，避免浏览时无条件生成完整像素。
4. **离线优先。** 浏览、编辑、元数据和导出均不依赖云端服务。
5. **可预期。** 不收集用户内容，不内置广告，不静默改写文件或元数据。
6. **键鼠高效。** 高频动作有稳定快捷键，常用任务可在三步内完成。
7. **能力可降级。** GPU、系统 codec 或某种格式不可用时，应给出明确提示并尽可能回退。

## 3. 支持平台与发布方式

### 3.1 平台基线

- Windows 10 22H2 x64；
- Windows 11 x64；
- ARM64 在核心功能稳定后单独验证；
- 首版不提供 x86 构建。

### 3.2 发布

- **当前交付：EXE 安装器**，0.4.0 沿用 Inno Setup 当前用户安装、升级、卸载与文件关联候选；无需管理员，当前未签名；
- **目标主渠道：MSIX**，待稳定签名身份与打包模型确定后提供安装、卸载、文件关联和更新；
- **辅助渠道：便携 ZIP**，不承诺与 MSIX 完全相同的资源管理器集成；
- 所有本地 native 库必须随包固定版本，不依赖用户机器预装开发运行库。

当前 CI 产出 self-contained win-x64 应用、版本化 EXE 安装器/便携 ZIP 与 SHA-256 清单，安装版与便携版关联身份独立，并配置安装、升级、卸载和真实 EXE 激活检查；通过手动 Actions 可选择仅构建或在 master 上按需创建 GitHub Release，发布精确提交的版本 tag、EXE、便携 ZIP 和两份 SHA-256；已发布版本不覆盖。操作与失败恢复见 [GitHub 发版说明](github-releases.md)。本轮开发不触发 Release，普通 CI 仅生成验证 artifacts；提高开发版本号不代表已经公开发布。产物尚无可信签名，MSIX 与正式签名发布未完成。基本“打开方式”和双击文件属于 M1；用户在系统界面选择默认应用，应用不静默设置默认程序。真实 Shell 使用与安装边界见文件关联方案。

## 4. 核心使用场景

### 场景 A：立即查看

双击图片后尽快显示可辨认内容；用户可直接缩放、平移，并浏览同目录上一张或下一张。

### 场景 B：快速处理截图

从文件、拖放或剪贴板打开图片，裁剪、缩放、加箭头或马赛克，然后复制结果或另存为。

### 场景 C：预览摄影文件

先读取 RAW 内嵌预览并展示基础拍摄信息；需要时后台进行完整解码。

### 场景 D：转换与导出

将当前图片导出为 JPEG、PNG 或 WebP，并控制品质、尺寸、元数据保留策略和颜色空间。

## 5. 功能范围

### 5.1 MVP：浏览与基础编辑分阶段交付

M1 先完成可靠浏览与基础信息，以下基础编辑和导出在 M2 交付；格式扩展按 M0 验证结果逐项进入正式支持。

#### 打开与导航

- 双击、文件选择、拖放、命令行路径和剪贴板打开；
- 同目录上一张/下一张，支持预取相邻图片；
- 适应窗口、实际像素、全屏；
- 鼠标滚轮缩放、拖拽平移、双击切换适应窗口/实际像素；
- 图片加载、损坏、格式不支持和权限错误均有明确状态。

#### 文件与图片信息

- 文件名、路径、格式、尺寸、文件大小和修改时间；
- 常见 EXIF：相机、镜头、ISO、快门、光圈、焦距、拍摄时间、方向；
- GPS 默认只显示信息，不主动联网解析地址；
- 复制路径、复制图片、复制选定元数据。

#### 基础编辑（M2，浏览器稳定后交付）

- 90° 旋转、任意角度预览、水平/垂直翻转；
- 自由裁剪与 1:1、4:3、3:2、16:9、9:16 比例；
- Resize：保持宽高比；
- Stretch：允许独立指定宽高；
- 撤销、重做、重置；
- 编辑操作以参数链保存，确认导出前不改写原始像素。

#### 首版输入格式

- 必须支持：JPEG、PNG、BMP、GIF、TIFF、WebP、ICO；
- 条件支持：HEIF/HEIC、AVIF，取决于随包 codec 能力；
- SVG 采用隔离的矢量渲染路径，默认禁止外部资源和脚本；
- 动画 GIF/WebP 首版至少能播放、暂停并逐帧查看。

#### 首版导出格式

- JPEG、PNG、WebP；
- JPEG/WebP 品质；
- 保留或移除元数据；
- 输出尺寸、覆盖策略；
- 默认转换为 sRGB；若选择保留原 profile，应明确标识。

### 5.2 v1.0：补齐日常编辑

- 曝光、亮度、对比度、Gamma、饱和度、色温；
- 锐化与模糊，所有调整均支持实时预览和撤销；
- 箭头、矩形、椭圆、自由画笔、文本、马赛克、区域模糊；
- JPEG XL 读取作为实验能力，兼容性达标后再转为正式支持；
- RAW：DNG、CR2/CR3、NEF、ARW、RAF、RW2、ORF、PEF；
- PSD 仅显示可用的合成预览，不解析图层；
- 幻灯片体验完善（基础循环播放已在 M1 实现）；
- 用户可配置快捷键；
- 保存常用尺寸、裁剪比例和导出参数为预设。

### 5.3 v1.x：批处理和 Windows 集成

- 批量转换、缩放、压缩、重命名和水印；
- 资源管理器集成完善（基本“打开方式”和双击关联已前移至 M1）；
- 受 Windows 版本和安装方式约束的右键转换入口；
- 多窗口；
- 文件变更监控与外部修改冲突提示。

### 5.4 长期候选，不作当前承诺

- OCR、二维码识别；
- 可扩展命令或导出器；
- 插件系统仅在稳定扩展点和安全模型明确后评估。

## 6. 明确不做

- 图层、蒙版、通道、钢笔、复杂选区；
- 曲线、HSL 分区、专业降噪和镜头校正；
- PSD 编辑和专业 RAW 工作流；
- AI 去背景、消除、扩图或云端生成；
- 资源管理、图库数据库、人脸识别和云同步；
- 首版批处理、插件系统和多窗口。

## 8. 技术选型

### 8.1 推荐基线

| 领域 | 选择 | 说明 |
|---|---|---|
| 语言与运行时 | C# + .NET 10 LTS | 当前 LTS，适合新长期项目 |
| UI | WPF | Windows 10/11 覆盖成熟，桌面集成和自绘承载稳定 |
| 画布渲染 | SkiaSharp 4 | 统一 CPU/GPU 绘制、缩放、几何变换和标注预览 |
| 常见格式 | WIC + SkiaSharp WebP | 当前 WIC 读取 JPEG/PNG/BMP/GIF/TIFF/ICO，SkiaSharp 补充 WebP；其他系统 codec 不自动纳入支持 |
| 大图与现代格式 | libvips | 缩略图、区域/顺序处理、导出和低内存流水线 |
| RAW | LibRaw | 内嵌预览优先，完整解码异步 |
| 元数据 | MetadataExtractor + 各 codec 元数据接口 | 读取常用 EXIF/XMP；ICC 由图像管线处理 |
| 架构 | 模块化单体 + MVVM | 保持边界清晰，不提前引入插件复杂度 |
| 测试 | xUnit + BenchmarkDotNet | 单元、集成、性能回归 |
| 日志 | Microsoft.Extensions.Logging | 本地滚动日志，默认不上传 |
| 发布 | self-contained MSIX / ZIP | 不要求用户安装 .NET Runtime |

### 8.2 为什么不选原草案路线

- **不选 .NET 9：** 它是 STS；新项目应以 .NET 10 LTS 为基线。
- **不把 WinUI 3 作为首选：** 本项目更依赖成熟的 Windows 10 桌面能力、启动路径控制和自定义高性能画布。WPF 可以实现 Fluent 外观，且工程风险更低。
- **不使用 WPF + Native AOT：** 当前没有官方支持的 WPF Native AOT 生产路径。发布采用 self-contained，并评估 ReadyToRun；优化重点放在依赖数量、首屏路径和延迟初始化。
- **不以 ImageSharp 作为主显示管线：** 它适合托管图像处理，但查看器还需要大图低内存解码、RAW、动画、系统 codec 与 GPU 画布。可在纯托管算法确有价值时局部使用，而不是承担全部编解码和显示职责。

### 8.3 编解码优先级

```text
文件识别
  ├─ WIC：当前 JPEG/PNG/BMP/GIF/TIFF/ICO 静态读取
  ├─ SkiaSharp：当前 WebP 静态读取
  ├─ libvips：大图、现代格式、缩略图、导出
  ├─ LibRaw：RAW 内嵌预览与完整解码
  └─ 专用安全渲染器：SVG 等主动内容风险格式
```

检测应基于文件签名与解析结果，不只依赖扩展名。解码器必须有尺寸、像素数、帧数、递归和内存预算限制。

### 8.4 色彩管理

- 读取嵌入 ICC profile；
- 无 profile 图片默认按 sRGB 解释；
- 预览转换到当前显示器 profile；
- 导出默认转换并嵌入 sRGB；
- 广色域保留作为显式选项；
- Alpha 预乘、EXIF Orientation 和 HDR/高位深行为必须由测试样本固定。

当前仅已实现常见 JPEG EXIF 与方向纠正；统一 MetadataExtractor/XMP、ICC 显示转换和导出仍为后续能力。

## 9. 软件架构

```text
ModernImageViewer.App          WPF 启动、窗口、依赖装配
ModernImageViewer.UI           View、ViewModel、命令、主题
ModernImageViewer.Application  用例、编辑会话、撤销栈、导航
ModernImageViewer.Imaging      图像模型、渲染、变换、色彩管理
ModernImageViewer.Codecs       WIC/libvips/LibRaw 适配器
ModernImageViewer.Metadata     EXIF/XMP/ICC 读取与导出策略
ModernImageViewer.Platform     文件关联、剪贴板、Shell、更新
ModernImageViewer.Tests        单元与集成测试
ModernImageViewer.Benchmarks   启动、解码、切图、导出基准
```

### 9.1 核心接口

- `IImageDecoder`：探测、快速预览、完整解码、帧读取；
- `IImageEncoder`：格式能力、导出参数、元数据策略；
- `IImageSource`：原文件、剪贴板或流的统一抽象；
- `IRenderSurface`：画布呈现与 GPU/CPU 回退；
- `IEditOperation`：不可变编辑参数，可组合、撤销和重做；
- `IMetadataReader`：统一元数据模型；
- `IFileSequenceService`：目录枚举、排序和相邻预取。

### 9.2 线程与内存模型

- UI 线程只做输入、布局和提交渲染；
- 探测、解码、缩略图、元数据和导出在后台执行，并支持取消；
- 切图时取消过期任务，结果写回前核对请求版本；
- 使用有界缓存，按解码后像素内存而非文件大小计费；
- 超大图优先使用缩略图、分块或降采样解码，不无条件生成完整 RGBA 位图；
- GPU 不可用、设备丢失或远程桌面场景回退到 CPU。

## 10. 非功能需求与验收基线

性能数字须在固定基准机、Release x64、self-contained 包、杀毒软件保持系统默认的条件下测量，并同时报告 P50/P95。

### 10.1 建议基准机

- Windows 10 22H2 与 Windows 11 各一台；
- 4 核以上近五年主流 CPU；
- 16 GB RAM；
- NVMe SSD；
- 1920×1080、150% DPI；
- 集成显卡作为最低 GPU 基线。

### 10.2 指标

| 指标 | MVP 门槛 | v1.0 目标 |
|---|---:|---:|
| 热启动至首个可交互窗口 P95 | ≤ 350 ms | ≤ 250 ms |
| 冷启动至首个可交互窗口 P95 | ≤ 1,000 ms | ≤ 700 ms |
| 24 MP JPEG 首个可辨认画面 P95 | ≤ 500 ms | ≤ 350 ms |
| 已索引目录相邻切图首屏 P95 | ≤ 200 ms | ≤ 120 ms |
| 4K 图片缩放/平移 | P95 帧时 ≤ 33 ms | P95 帧时 ≤ 16.7 ms |
| 空闲工作集 | ≤ 180 MB | ≤ 140 MB |
| 连续浏览 500 张后的不可回收增长 | ≤ 100 MB | ≤ 50 MB |
| 100 MP 图片 | 不崩溃且可取消 | 5 秒内出现降采样预览 |

原草案的“100 MB 图片 1 秒内打开”不作为指标，因为压缩格式、像素数、位深和帧数差异过大。

### 10.3 稳定性与安全

- 损坏文件不得导致进程崩溃；
- 解码任务均支持取消和超时；
- SVG 默认禁用脚本、网络、文件访问和外部字体加载；
- 防止解压炸弹：限制最大像素数、帧数、单帧内存和累计解码预算；
- 崩溃恢复不得自动覆盖原图；
- 日志不得记录图片内容、完整 EXIF GPS 或未经用户允许的完整路径；
- native codec 版本和许可证纳入 SBOM，并定期更新。

## 11. 测试策略

### 11.1 测试资产

建立可再分发的固定图像语料库，覆盖：

- 每种支持格式的最小、典型、超大、损坏样本；
- 1/8/16-bit、灰度、CMYK、Alpha、动画、多页 TIFF；
- 各 EXIF Orientation；
- sRGB、Display P3、Adobe RGB、无 ICC 和损坏 ICC；
- 高压缩比、异常尺寸、超多帧和截断文件；
- 不同厂商 RAW 及仅含/不含内嵌预览的样本。

### 11.2 测试层级

- 单元测试：尺寸计算、编辑参数、撤销栈、排序、元数据映射；
- 金图测试：解码、旋转、裁剪、颜色转换和导出像素差异；
- 集成测试：打开、切图、导出、取消、文件被外部修改；
- UI 自动化：主路径、键盘导航、DPI、主题；
- 模糊测试：文件头、元数据、帧表和 SVG；
- 性能回归：启动、首屏、切图、缩放、峰值内存、长时间浏览。

发布阶段在固定基准机上确认的性能回归超过基线 10% 时阻止发布，除非有记录的原因和批准。日常验证按变更风险精简：文档只检查一致性和链接，视觉调整抽查关键界面；像素生命周期、取消、缓存、导出及安装路径补针对性验证。复用既有 CI，不为低风险变化增加重复测试或全量矩阵。

## 13. 风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| native codec 依赖和许可证复杂 | 阻塞分发 | M0 建立 SBOM；逐项审查 LGPL、HEVC/AV1/JXL 依赖和动态链接方式 |
| HEIF/RAW 行为受 codec 与设备影响 | 格式承诺不稳定 | 随包固定 codec；显示实际可用能力；建立厂商样本库 |
| WPF 与 Skia 画布互操作开销 | 帧率或内存不达标 | M0 测量拷贝路径；复用 surface；必要时改用原生 D3D 互操作 |
| ICC/广色域实现不完整 | 颜色错误 | 固定颜色测试图和显示器 profile 测试；v1 前不承诺 HDR |
| 大图或动画导致内存爆炸 | 崩溃与安全问题 | 有界缓存、降采样、分块、帧预算和取消 |
| 功能范围持续膨胀 | 延期 | MVP 只做浏览与基础信息；编辑、RAW、标注分里程碑进入 |
| Shell 扩展增加部署风险 | 安装与稳定性问题 | 基本文件关联使用系统支持的注册方式在 M1 完成；复杂右键转换和进程内扩展延后到 v1.x |

## 14. 发布门槛

下面是 v1.0 正式发布的验收门槛。当前 0.x GitHub Release 属于开发预览分发：至少完成对应构建、格式/关键回归、包校验与安装 smoke，随版本准确记录未完成的签名、Shell 人工验收与性能测量；不能因上传 Release 就宣称以下目标全部达成。普通 CI 不自动发布，用户手动选择发版；详见 [GitHub 发版说明](github-releases.md)。

v1.0 版本只有同时满足以下条件才可发布：

- P0/P1 已知缺陷为 0；
- 支持格式语料库全部通过，未支持能力在 UI 中准确说明；
- Windows 10/11 安装、升级、卸载、文件关联验证通过；
- 基准机性能不低于对应里程碑门槛；
- 连续浏览、取消、损坏文件和低内存测试无崩溃；
- 第三方依赖、许可证、NOTICE 和 SBOM 完整；
- 原图覆盖、元数据移除、颜色转换等高风险操作有自动化测试。

## 15. 待确认的产品决策

在相关能力进入正式发布前需要确定；这些决策不阻塞现有静态格式浏览开发：

6. 是否承诺完整色彩管理，还是首版统一以 sRGB 显示和导出。
