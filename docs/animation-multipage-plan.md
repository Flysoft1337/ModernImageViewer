# 0.6 动画与多页实施方案（已确认，开发与自动化验收完成）

核对基线：master `9cdcde9`，0.5 浏览核心收口已合并。用户已确认方案，统一会话、共享时钟及codec已完成自动化验收；实际结果及仍待补的固定机性能/设备验证见[验收记录](animation-multipage-validation.md)。本文件保留设计与验收要求，不发布Release。

## 现状与必须处理的边界

指定的 AGENTS、README、project-plan、next-iteration-roadmap、feature-expansion-plan、decoder-support、browsing-core-closeout 已核对。

| 现有实现 | 为什么不能直接扩为动画/多页 |
|---|---|
| `ImageOpenState` 保存一份 PixelBuffer、预览和区域 | 无页/帧身份、帧时间、循环、依赖和 disposal；局部帧不能直接充当整张图片 |
| WIC 的主图、区域均取 `Frames[0]` | TIFF 后续页无入口；BitmapImage 缩放重新读取首页，不能简单修改帧索引 |
| WebP 的 SKCodec 默认 GetPixels，调用后关闭 codec/stream | 当前仅验证首帧；动画需持有解码上下文、帧依赖及受控合成状态 |
| 文件打开生成新 Source.Identity，并提交目录当前位置 | 用重复 OpenAsync 播帧会重置视口和目录语义，且重复打开/扫描 |
| 所有 coordinator 状态通知到 VM 都 NotifyAll | 每帧会波及目录、菜单和全部绑定，不适合作为播放热路径 |
| MainWindow 每次 VM 属性通知都重启 F6 timer | 动画帧或页码通知会反复推迟文件幻灯片的切换 |
| DPI/完整/区域细化仍按文件路径读取 | 播到后续帧/页时，旧静态任务可能把首帧/首页重新盖回画布 |
| SharedPixelBitmap pin 当前数组；复制操作也持有 ReadOnlyMemory | 不能后台改写、提前归还或直接轮换仍被消费者引用的数组 |
| 预取只保存 PixelBuffer | 预取只提供代表帧，不能把活动播放会话放进邻图缓存 |
| WPF BitmapDecoder 与 BitmapFrame 有线程边界 | 持久会话需核对线程访问，不能让任意 Task.Run 线程轮流使用未冻结对象 |

已有 DIP/物理像素/源像素模型、前台优先调度、文件戳、打开代次、旧画面保留及缓存失效继续复用。HEIF/AVIF、RAW、受限 SVG 的静态路径和编辑能力不扩大范围。

## 最小统一帧模型

普通静态图片概念上为一个无时长的完整帧；实现继续使用现有 PixelBuffer，不分配帧列表、播放器、timer 或常驻工作线程。仅实际有动画/多页时创建可释放会话。

| 层级 | 设计职责 |
|---|---|
| 图片来源 | 现有 ImageSource.Identity、真实文件/内存来源、文件版本；不随播放变化 |
| FrameSequenceInfo | Static / Animation / Pages、总数、总有效时长、规范化循环、随机访问策略；静态默认值复用 |
| FrameDescriptor | 索引、逻辑画布尺寸、局部源像素矩形、原始/有效时长、Source/Over 混合、Keep/Background/Previous 销毁、依赖帧和是否需要重新合成 |
| IImageFrameSession | 会话元信息、按目标/预算读取指定帧或页、取消、显式 Dispose；codec 负责格式适配，不负责 WPF 定时 |
| ImageFramePresentation | 当前页/帧索引、视口内容身份、完整画布 PixelBuffer、像素交接租约；不更改目录索引 |
| FramePlaybackController | 独立的播放、暂停、恢复、结束、重播、定位和时间推进；GIF/WebP 共用，TIFF 只使用内部导航 |
| WPF 时钟适配 | 懒创建 DispatcherTimer + 单调时间；窗口可呈现性与用户暂停分开处理 |

只在 Application/Images 新增窄接口和控制器，在 Imaging 放无 WPF/codec 依赖的数据类型。MainWindow/VM 使用局部接入或独立轻量帧控件，不把格式处理和播放实现继续塞入主类。

视口身份为来源加逻辑页面：动画的逻辑页面始终为同一画布，帧索引不重置视口；TIFF 换页产生不同页面身份，即便页面尺寸相同也不能沿用旧页区域。当前页的预览升级保留该页视口。不同来源始终重置。

循环统一表达为无限或总播放轮数，保留原始容器值供诊断：GIF 无循环扩展为播放一次，Netscape 的有限重复次数转换为首次加重复；WebP 按 ANIM 语义转换。不能直接把不同格式的原始数值混用。实施时用固定有限/无限样本核对实际 codec 的 repetition 语义。

## 合成与 codec 路线

1. GIF 先完成。使用已有 WIC/Skia 的真实解码能力，不手写 LZW。先以固定像素样本核对 raw/composited 输出、局部区域、透明、offset、background 和 previous。若 Skia GIF 不能在预算内降采样，使用 WIC 的局部帧缩放与有界合成适配；不能先展开全源 BGRA 再宣称有界预览。
2. 可复用合成状态按完整逻辑画布维护。上一帧显示完毕后执行其 disposal，再准备当前帧的 previous 快照，按 Source/Over 合成当前局部区域。previous 只保存所需区域，所有快照计费。初始背景和透明背景由格式语义及固定样本决定。
3. codec 若已合成完整帧，适配层明确标记完整输出并使用其依赖接口，不能再重复 blend/disposal。缺失的格式元信息只做有界结构读取，像素压缩仍交给现有 codec。
4. TIFF 保留当前文件/decoder 会话与页面索引，按页读取尺寸、方向和目标像素；不每翻一页重扫整个文件。WPF 会话只在其允许的线程使用，必要时采用仅多帧会话创建的单一串行 worker；静态/单页路径不承担常驻线程。当前页的完整/区域读取必须携带页索引。
5. WebP 在 GIF 合成与播放测试稳定后接入同一契约。逐项核对 ANIM/ANMF、帧矩形、alpha、blend、dispose、duration、loop 与 SKCodec FrameInfo/RequiredFrame/PriorFrame。不能由静态 WebP 测试推导动画能力。
6. 优先不新增 native 依赖。只有已有 codec 无法满足正确性和预算时才评估最小补充；添加前核对许可证、版本、安全审计、架构、实际包体/native 文件、构建及完整 NOTICE/源码要求，并记录实测依据。

单帧 GIF、单页 TIFF、静态 WebP 无播放浮层，不启动播放时钟。中途损坏帧停止播放并保留最后有效画面，反馈本地化错误；首次不可解码沿用当前错误和旧图保留流程。

延时拟采用明确兼容策略：GIF 的 0/10ms 极短延时回退 100ms，20ms 及以上保留有效声明；非法数值拒绝或明确回退，不驱动零间隔循环。WebP 原始与有效时长分开记录，具体极短延时规则以固定样本/API 语义核对后固化。有效总时长用于时钟与展示，不能和原始总时长混淆。

## 调度、时间与生命周期

- 前台文件打开最高；内部用户定位/翻页次之；播放帧任务低于前台打开，缩略图和邻图仍最低。复用 DecodeScheduler，不能建立一个绕过前台优先的动画池。
- 每个会话最多一个帧任务在途，仅保留最新目标。解码/合成在后台，UI 线程仅原子提交和重绘。
- 使用单调时间计算应呈现位置，timer 只负责唤醒；错过视觉帧可以省略绘制，依赖合成仍正确。补合成分段、有取消点，不能在 UI 线程连续补几十帧，也不能长占主槽挡住新打开。
- 用户暂停冻结有效播放时间；因最小化、不可见、失活或 viewport 卸载而暂停是独立状态。恢复可见性不解除用户暂停，也不追赶整个隐藏期间的帧。
- 切图/F5/重新打开开始即停止旧时钟、取消会话代次、阻止晚提交；关闭/Dispose 同样处理。已执行 native 等实际返回后释放，不伪造立即取消。
- 文件打开代次、会话代次、内部定位代次和文件戳共同校验；只有最新目标可提交。失败保留旧像素，但旧播放器不得因回滚静态状态复活。
- 当前会话释放 codec、流、compositor、快照、timer、pin、bitmap；运行任务在 finally 释放，晚结果不可回填帧缓存/缩略图/邻图。
- 静态完整/区域/预览任务在接管时取消；后续需求路由到当前帧/页，动画不叠旧 ROI。目标变化沿用 350ms 稳定与升级阈值，完成前保留画面及视口。
- 帧内容通知仅更新必要画布和帧状态，不读取目录/文件属性，不触发 NotifyAll 或 ScaleChanged。F6 只因文件加载/文件切换/用户间隔/播放状态及窗口状态更新；内部帧与页不重置它。

## 像素与缓存预算

实施初始帧像素总预算拟定为 **32MiB**，独立计费且纳入原有160MiB主图交接边界；不能在主图预算外任意增长。预算包含应用掌控的显示帧、待交接帧、合成工作画布、局部解码输出、参考帧和 previous 快照。

目标从可见 DIP 乘双轴 DPI 得到，再按源尺寸、4096 单边和同时存在的缓冲需求缩小。以最坏当前资源份数预留后再分配，不按“缓存三帧”忽略字节。首版可以牺牲超大动画预览分辨率，不能越过预算或默认展开全部帧。

只缓存必需状态；可重新计算的参考/检查点有空间才存，压力下先移除。UI/SKBitmap 或复制消费者仍持有的数组不得改写；缓冲池若采用租约，最后消费者释放后才能复用。不能把现有裸 ReadOnlyMemory 自动当成租约，复制期间需冻结快照或暂停交接。

TIFF 当前页继续沿用静态预览/完整/区域预算，不保留全部页面 BGRA。缩略图仍静态代表帧/首页，24项/2MiB；邻图仍单项4MiB，不持有活动会话。必要新增输入256MiB、元信息2MiB、帧/页数10,000的上限；源单边32768/100MP约束不放宽。所有数值进入显式政策与超限测试，最终文档以实际实现/验收为准。

native 内部缓存、编码来源缓存和绘制 surface 单独列观察，不能把32MiB称为进程峰值硬上限。记录原生会话数、应用掌控像素字节与实例数；不强制 GC。

## UI 与现有功能边界

- 底部工具栏附近按需显示轻量帧控制区，与沉浸浮层共用可见性。动画：播放/暂停、当前帧/总帧、重播、帧定位；TIFF：上一页、页码输入/总页、下一页。普通图片完全不显示。
- 复用现有图标、主题、字体、焦点和工具提示，固定状态文本宽度，720×480、中英文、深浅主题及四档 DPI 检查不遮画布/工具条。
- 建议 `Ctrl+PageUp/PageDown` 内部前后帧/页，`Ctrl+Home/End` 内部首尾，`Ctrl+Space` 动画播放/暂停；手动选帧暂停自动播放。保留左右/Home/End文件导航、F6/Space文件幻灯片，新增动作同步 F1 并避让文本输入。
- 信息面板仅在有内容时展示帧数/当前帧/循环/有效总时长或页数/当前页；不添加空字段，不以每帧重建全部 EXIF 行。
- F6 按文件停留时间切换，不等待动画完整循环。切换即停止并释放旧动画。
- 不扩 EditWindow。多帧/多页入口不得让现有静态导出误读首页：本轮编辑与原尺寸复制按已明确的静态能力启用，不能暗示动画编辑/动画导出或所选 TIFF 页导出已经支持。最终接入时准确提示边界；普通静态编辑能力继续回归。

## 实施与验收顺序

1. 保存0.5固定基线与验证参数；帧契约、时钟、预算和代次测试，验证静态图片不创建会话/时钟。
2. 固定 GIF 样本与合成测试，然后自动播放、暂停恢复、定位、循环、结束；先通过像素/生命周期关卡。
3. TIFF 单页/多页/异尺寸/异方向/损坏页的会话翻页；同文件导航不改变目录位置，页细化不回首页。
4. WebP 静态/动画/透明/局部/Source-Over/dispose/有限无限循环，复用同一时钟和状态。
5. 集成轻量 UI、快捷键、元数据、F6 隔离，补切图/F5/native 晚完成/unload/reload/Dispose/复制快照及四档 DPI/视口保持回归。
6. 专项观察和全量已有 CI，按实测修正声明并提交 PR；必要检查通过后按既有授权合并，不调用 Release 发布。

固定样本采用项目自有、可再分发的确定文件，附生成依据/哈希与预期像素。GIF 至少覆盖用户列出的单帧、常规、透明、局部、background、previous、无限/有限、极短、损坏、大尺寸；TIFF 覆盖单页、多页、异尺寸和损坏；WebP 覆盖静态、动画、透明、局部、blend/dispose及有限无限。合成验证固定位置/整帧哈希，不只验证没有异常。

压力方案覆盖长循环、大动画、连续动画切换、GIF/WebP/TIFF/JPG交替、缩放平移、全屏往返、F5与关闭；记录 WS/private/handle 与 active PixelBuffer/SKBitmap/native decoder/timer/快照字节。停播和切图后应用掌控资源必须有明确上限及归零/回落或稳定趋势，不能由短 CI smoke 宣称整个进程永不泄漏。

最终执行适用 format、Release build、完整测试、依赖审计、既有100MP/startup/browsing observation与新动画专项、文件激活、安装、真实0.5→0.6升级、同版本重装、卸载。现有 check-installer 的 upgrade.log 实际为同版本重装加旧注册迁移，需要显式传入基线安装器才能证明跨版本升级，不能复用旧报告冒充。

最终版本改为0.6.0开发版的时点在实现分支，0.5基线独立保留；本方案阶段不改版本，不发布任何 GitHub Release。README/decoder-support矩阵分别列静态、动画、多页、透明、ICC、EXIF、区域与现有编辑边界，以固定样本和CI实际结果更新。提交、测试数量、观察环境和原始结果均如实记录。

## 待实施验证项

SKCodec GIF的缩放、raw/composited、restore previous及loop语义，WebP帧字段和WIC会话线程/释放行为需要先做小型实际probe；本方案不把API名称当成功证据。若发现现有codec无法在预算内正确实现，记录具体样本与限制后再调整adapter，不扩大产品范围或复制第二套播放器。
