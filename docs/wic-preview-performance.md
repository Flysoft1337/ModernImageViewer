# WIC 无缩放预览性能记录

2026-10-19，基线 `1015e0c`。本批保持0.6.1，不发布。

## 改动范围

WIC先建立BitmapDecoder读取首帧和元信息，原先只要指定预览包围盒，就会重置输入并另建BitmapImage/OnLoad，即使源图已经完全落在包围盒内。常规、无ColorContext的Bgr24/Bgr32/Bgra32/Pbgra32现直接从已有frame输出预乘BGRA，省去第二次初始化及其OnLoad缓存。

需要缩小、带ColorContext、CMYK、高位深及其他像素格式仍走原BitmapImage路径；读取ColorContext异常时也回退原路径。方向纠正、文件stamp、取消/晚结果释放、调度、像素预算和原图只读约束不变。没有增加缓存，也没有宣称native缓存或进程内存会立即归零。

## 同机局部对照

Windows本机i7-11800H、32GiB，framework-dependent Release。临时harness同时编译原WIC类（只改类名）和修改后的类，直接调用同步WIC核心：同一进程、同一份只读内存编码输入，1对预热后6对AB/BA交替，每组12次。每组首张的像素SHA-256也包含在耗时内。没有强制GC；所有对的输出哈希相同，结束时受控PixelBuffer计数为0。

样本由WPF编码，BGRA像素为B=x mod256、G=y mod256、R=(x+y) mod256、A=32+(x mod224)。PNG使用PngBitmapEncoder，JPEG使用默认JpegBitmapEncoder。不是摄影样本或磁盘冷读。

## 回归和未完成项

- 扩展既有格式用例，验证等大/较大包围盒不放大，像素与完整输出一致，包含透明PNG及现有WIC容器；既有8种JPEG方向用例增加两类无缩放预览的逐字节/元数据比对。
- 仅新增1个独立用例：带非sRGB ICC的JPEG预览与旧BitmapImage路径输出一致，并保持Orientation6。该固定样本旧路径输出灰度128，不能据此宣称浏览WIC已具备完整ICC转换；编辑导出RGB ICC→sRGB能力另有既有测试。
- 本地format verify、Release构建0警告0错误；完整190核心+423 UI/codec=613通过，1项真实RAW样本跳过；当前源依赖审计未报告漏洞。
- 既有100MP单次观察：预览1600×1600/10,240,000字节、271.28ms；缩略图140×140/78,400字节、220.75ms。非对照，不推导提升。文件哈希及完整记录在上述目录的`100mp.json`。
- 原[历史CI39172850861](https://github.com/Flysoft1337/ModernImageViewer/actions/runs/39172850861)有效切图比值1.12247665失败保留。此前[父版本诊断39174874261](https://github.com/Flysoft1337/ModernImageViewer/actions/runs/39174874261)第一轮六对有效、切图比值0.99757668，第二轮失焦零对且整个job失败；只说明未复现稳定回退，不能将原失败改判通过。
- 本批复用PR #48既有Windows CI，结果以新提交检查为准；不改变10%门槛，不复用旧发布风险审批。完整UI切图性能、真实桌面/混合DPI及长期跨设备观察未由上述测量证明完成。
