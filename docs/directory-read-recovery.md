# 目录读取失败反馈与恢复

2026-10-21源码小批，基线fa98b25（依赖PR #49），版本0.6.2，未发布。不增加编辑、监听、解码格式或常驻面板。

## 已确认问题

目录枚举原先捕获IO/权限异常后返回空数组或仅当前文件：打开文件夹时误报“没有图片”，F5可能把已有目录列表缩成单项。显式OpenFolderAsync原先转为普通输入，目录被删除后又因Directory.Exists=false归为没有支持文件。

## 实际改动

- 枚举失败继续向上报告，由明确打开文件夹及F5边界捕获IO/权限错误；真正枚举成功但零候选仍显示空目录。
- 显式打开保留文件夹意图，即使其已被删除或变成普通文件，也给出目录读取失败反馈。
- 沿用现有主题消息浮层，增加中英文读取失败/访问拒绝提示，不输出异常消息或用户路径。
- 扫描成功后才提交完整列表；失败保留原画面、列表和位置，恢复加载状态并停止幻灯片。恢复访问后重新打开文件夹或按F5可重试。
- 失败消息受当前输入版本、取消及Dispose检查保护，迟到的系统读取错误不覆盖后来的图片/消息。

缓存仍按既有F5规则失效，解码、原文件只读、首屏/细化和像素预算不变。失败不把已取消的动画会话恢复为播放；只保证保留最后画面。系统已执行的目录读取不能保证立即取消，真实返回后丢弃旧错误。通过单个图片打开后后台索引不可读时，仍沿用既有单项回退，本批不新增该路径的专门提示或持续目录监听。
