## 2. 实施顺序

优先级仅用于安排下一轮工作：P1 为近期，P2 为浏览器稳定后的下一阶段，P3 为后续版本。发现崩溃、原图损坏或持续内存增长时优先修复；表内项目不是并行开发承诺。

| 顺序 | 优先级 / 阶段 | 工作包 | 完成条件 |
|---|---|---|---|
| A | P1 / M1 | 路径/重复激活/便携关联已实现；后续安装版关联与 Shell 验收 | Windows 10/11 上选择应用后双击 JPEG/PNG 可打开正确文件；已有窗口可接入；卸载清理可验证 |
| B | P1 / M1 + M0 验证 | 首图与大图：渐进预览、目录索引解耦、总内存预算 | 第一张可辨认画面不等待整个目录；100MP 样本可取消且有降采样回退；预算包含主图、在途任务和缓存 |
| C | P1 / M1 | UI 收敛：紧凑布局、沉浸全屏、状态与焦点 | 窄窗口、高 DPI、长文件名和中英文无裁切；全屏可隐藏控件且键盘仍可退出；错误可恢复 |
| D | P1 / M1 | 连续浏览：预算内预取、缓存失效与排序 | 连续切图只提交最新请求；前台打开优先于预取；F5/外部修改不会显示旧缓存；排序稳定 |
| E | P2 / M0 + M1 | 格式、动画/多页、色彩管理 | 按格式逐个交付能力矩阵与固定样本；选择器、导航、缩略图、关联和说明同步更新 |
| F | P2 / M1 收尾 + M2 | 日常工作流与安全编辑 | 剪贴板、定位文件、快捷键帮助；随后交付非破坏性编辑与另存为，覆盖保存有明确风险提示 |
| G | P2 / M3 | 发布收敛 | Windows 安装/升级/卸载与实际双击路径、签名、依赖许可、基准机目标全部验收 |
| H | P3 / M3–M4 | 调整/标注、RAW 完善、批处理、多窗口 | 在浏览与导出稳定后逐项开展，不引入图库数据库或云同步 |

建议下一组 PR 按 A → B → C → D 拆分。A 的路径与实例接入先于注册关联；B 先记录基线再改管线；D 在 B 的资源所有权与预算明确后接入。MSIX 的签名与升级验收可以独立推进，不能以此宣称便携版已具备安装版集成。

## 3. 功能补全

### 3.1 近期浏览能力

- **打开入口统一：** 已实现文件选择、拖放和命令行共用管线、多选策略与窗口复用；MSIX 激活适配随后接入，详见文件关联方案。
- **日常文件操作：** 在资源管理器中定位、复制文件/图片、可复制的信息字段；近期先做读取与定位。删除、重命名随后加入，删除默认进回收站，失败保留当前显示和导航。
- **导航设置：** 增加名称/修改时间/大小排序及升降序；默认沿用自然名称排序。切换排序保留当前文件，处理同名排序键和外部删除。
- **窗口与偏好：** 保存正常窗口位置、缩略图/信息面板状态和幻灯片间隔；显示器移除时恢复到可见工作区。不自动打开历史文件，最近记录若增加需可清空、可关闭。
- **剪贴板：** 支持位图和文件列表输入、复制当前可见结果；内存来源没有原文件路径，不伪造目录导航或覆盖保存目标。透明像素、尺寸与大图预算与文件来源一致。
- **加载与恢复：** 加载可取消、错误可重试或跳过；不支持、损坏、权限拒绝、文件消失分别提示。当前已有错误分类与旧图保留，后续补操作入口和文件夹枚举错误的准确反馈。

### 3.2 格式、元数据与颜色

先建立“探测 → 缩略图 → 主图 → 导出”的统一能力表，再扩展 BMP、静态 GIF/TIFF、WebP、ICO。动画和多页作为独立能力交付，不能把第一帧解码标成完整动画支持。文件签名探测与扩展名不一致时给出明确结果。

HEIF/AVIF 要验证随包 codec 与系统扩展的差异，RAW 先展示内嵌预览；SVG 使用受限渲染路径。每加入一个 codec 同步检查 native 依赖、分发体积、许可证与损坏样本处理。

色彩管理单独推进：读取 ICC、无 profile 按 sRGB 解释、转换至显示器 profile、跨屏重新选择 profile，导出默认嵌入 sRGB。当前 EXIF 方向纠正不代表 ICC 或 HDR 已支持；16-bit、CMYK、广色域和 HDR 行为要明确记录。元数据展示支持选择复制，GPS 不主动联网解析。

### 3.3 编辑与导出

查看时旋转/翻转可先提供会话预览，明确区分自动 EXIF 方向与用户操作。M2 引入不可变操作链、撤销/重做、裁剪、Resize/Stretch，默认通过另存为导出 JPEG/PNG，再接 WebP。尺寸、质量、元数据移除和 ICC 策略应集中在导出面板。

编辑预览不得修改共享源像素。导出使用独立任务和预算，支持取消；输出先写临时文件再完成替换。覆盖原文件需要确认，关闭或切图时处理未导出状态。调整、标注、预设与批处理在此基础上推进。

## 5. 性能优化

### 5.1 已有基础及实际边界

- 启动已移除 Generic Host，窗口先显示，Skia 控件延迟到首次图片；后续关注首次图片初始化而不是重复引入启动优化。
- 主画布已共享解码数组，少一份完整渲染像素副本；WIC 转换、方向变换、原生解码和 surface 仍可能有其他分配，不能称整个管线零拷贝。
- 全尺寸解码已有单槽与排队取消；在执行中的 WIC 原生调用不保证立即中断，需测量取消延迟，必要时通过更适合渐进解码的 codec 改善。
- `ImageDecodeLimits` 限制单图尺寸 32768、像素数 100MP、输出字节 400,000,000；这是单图上限，不是进程总预算，也没有降采样主图回退。
- 目录枚举和排序已后台执行，但首次主图提交仍等待 `PrepareSnapshotAsync` 完成；超大目录可能拖慢可辨认画面出现。
- 缩略图缓存是按路径、数量限制的 FIFO；已有 F5 清理，但未按实际像素字节计费，也未基于修改时间自动失效。BenchmarkDotNet 当前仅覆盖像素数计算。

### 5.2 优化工作包

| 优先级 | 改动方向 | 判断是否有效 |
|---|---|---|
| P1 | 为启动、首个可辨认画面、完整清晰画面、目录可导航分别记录时间；使用无用户路径的阶段事件 | 发布包可区分窗口可见与图片首帧，固定样本结果可重复比较 |
| P1 | 主图先提交预览，目录索引独立完成；索引期间禁用依赖列表的操作并说明状态；请求版本贯穿预览/完整图/索引 | 万级目录打开单图不等待全目录，过期目录结果不会覆盖新会话；索引失败仍能查看已解码图片 |
| P1 | 依窗口和 DPI 选择首屏解码尺寸，逐步替换高分辨率；大图先降采样，再评估区域/分块解码 | 100MP 样本无需先分配完整 RGBA 才显示预览；实际大小与放大时细节正确，取消仍有效 |
| P1 | 总字节预算与显式资源所有权：可见图、旧图交接、在途解码、缩略图、预取、surface 都纳入 | 压力下先取消预取/逐出缓存/降采样；预算超限有反馈；失败与取消均释放资源 |
| P1 | 前台打开优先，预取按方向和预算最多准备邻近少量图片；隐藏缩略图停止非必要任务 | 预取不阻塞当前图片，不默认保存多张全尺寸大图；快速连续切图提交最后请求 |
| P2 | 以路径、修改时间、长度及渲染需求为缓存键，按字节上限做 LRU；文件监听采用去抖与合并，保留 F5 兜底 | 修改同路径图片后刷新可见，删除不崩溃；缓存命中与预算可观察，长期浏览不持续增长 |
| P2 | 将 UI 线程文件属性读取和大列表查找移出热路径；减少全属性通知，复用 checker/surface，合并无效重绘 | 网络路径、缩放/平移和万级目录不阻塞输入；以 UI 线程跟踪和帧时间确认收益 |
| P2 | 比较 ReadyToRun 的启动收益、包体增长；确认是否需要 GPU 画布，提供 CPU 回退 | 同机同样本实测后选择；兼顾集成显卡、远程桌面和设备丢失，不以 GPU 标签代替帧时数据 |

池化缓冲或 native 内存只在资源所有权明确且测量确有收益后引入；共享缓冲仍被 Skia 使用时不得归还、复用或改写。不通过强制全局 GC 掩盖回收问题。

### 5.3 测量与验收

以[项目计划的指标](project-plan.md#102-指标)作为目标，不将其标成当前已达标。保留现有启动 smoke，优化阶段在固定 Windows 机器比较前后 Release self-contained 包，记录提交、系统、CPU/RAM/磁盘、DPI、包配置、样本与观察窗口。

启动区分冷/热与首次启动；记录窗口可交互、首个可辨认画面、完整图完成。快速脚本默认 3 次、CI 1 次的结果只用于观察，不用来宣称 P95。阶段性能验收建议热启动/切图至少 30 次；冷启动记录受控重启条件和样本数，样本不足时列原始结果，不给可靠性不足的 P95 承诺。

样本至少含空窗口、4K PNG、24MP JPEG、100MP 图、透明/EXIF 图和万级目录。检查工作集、私有字节、托管堆、native 分配、峰值与取消后稳定值；连续浏览 500 张并观察缓存逐出后的趋势。正常交接可能暂存旧图和新图，应报告峰值而非只看打开后的工作集。

日常变更保持验证精简：文档/视觉调整只做相应检查；涉及像素生命周期、取消、缓存、导出和安装路径才补针对性回归。复用已有 CI，性能优化不扩展为每个 PR 的全量测量矩阵。

## 6. 完成标准与暂缓范围

每个工作包交付实现、用户说明和简短验证记录。支持新格式同时更新能力表与关联列表；界面优化附原生截图；性能优化附可复现条件和前后数据。记录目标值与观察值的差别，未实现入口保持隐藏。

M1 收尾需浏览主路径、文件关联、格式边界、DPI/键盘和性能基线明确；M0 高风险技术验证按能力推进，未通过的 codec/大图/ICC 不能进入正式支持。基础编辑从 M2 开始；批处理、复杂 Shell 扩展、多窗口、OCR、插件与图库数据库不进入近期工作包。
